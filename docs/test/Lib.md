### Third-party testing libraries

The `testing` package is enough but plain: assertions are hand-written `if` plus `t.Errorf`, and there is no mocking, no BDD, and no fuzzing. The five third-party libraries below each fill one gap; pick as needed.

#### 6.1 `testify`

`testify` is a popular Go testing library that provides assertions, mocking, and suites, making tests easier to write and maintain.

**Key features**:
- Assertions: a rich set of assertion methods, such as `Equal`, `NotNil`, and `Contains`.
- Mocking: supports generating mock objects and defining expected behavior.
- Suites: supports organizing test code with test suites.

**Install**:
```sh
go get github.com/stretchr/testify
```

**Usage example**:
```go
// example_test.go
package example

import (
    "testing"
    "github.com/stretchr/testify/assert"
    "github.com/stretchr/testify/mock"
)

// the Service interface and its mock
type Service interface {
    DoSomething() string
}

type MockService struct {
    mock.Mock
}

func (m *MockService) DoSomething() string {
    args := m.Called()
    return args.String(0)
}

// test example
func TestService(t *testing.T) {
    mockService := new(MockService)
    mockService.On("DoSomething").Return("Mocked Response")

    result := mockService.DoSomething()
    assert.Equal(t, "Mocked Response", result, "The response should be 'Mocked Response'")
}
```

#### 6.2 `gomock`

`gomock` is a mocking library officially supported by Go, providing the ability to generate and control mock objects. It integrates with the `mockgen` tool, which can generate mock code from an interface (the `NewMockService` function in the example is generated by `mockgen`).

> Note: `github.com/golang/mock` has been archived; the currently maintained fork is `go.uber.org/mock`, API-compatible, with the install command `go install go.uber.org/mock/mockgen@latest` and the import path `go.uber.org/mock/gomock`.

**Key features**:
- Mock code is generated from an interface by `mockgen`, and expected behavior is declared one call at a time with `EXPECT()`.
- Integrates well with `go test`.

**Install**:
```sh
go get github.com/golang/mock/gomock
```

**Usage example**:
```go
// example_test.go
package example

import (
    "testing"
    "github.com/golang/mock/gomock"
)

// the Service interface and its mock
type Service interface {
    DoSomething() string
}

// test example
func TestService(t *testing.T) {
    ctrl := gomock.NewController(t)
    defer ctrl.Finish()

    mockService := NewMockService(ctrl)
    mockService.EXPECT().DoSomething().Return("Mocked Response")

    result := mockService.DoSomething()
    if result != "Mocked Response" {
        t.Errorf("Expected 'Mocked Response', got '%s'", result)
    }
}
```

#### 6.3 `goconvey`

`goconvey` is a testing framework that provides enhanced assertions and BDD (behavior-driven development) style syntax, making test code more readable and better organized.

**Key features**:
- BDD style: nested `Convey` blocks map to "given/when/then", so the test structure reads at a glance.
- Assertions: declarative calls such as `So(result, ShouldEqual, 5)`, printing the actual and expected values on failure.

**Install**:
```sh
go get github.com/smartystreets/goconvey
```

**Usage example**:
```go
// example_test.go
package example

import (
    "testing"
    . "github.com/smartystreets/goconvey/convey"
)

// test example
func TestAddition(t *testing.T) {
    Convey("Given two integers", t, func() {
        a := 2
        b := 3

        Convey("When added", func() {
            result := a + b

            Convey("The result should be correct", func() {
                So(result, ShouldEqual, 5)
            })
        })
    })
}
```

#### 6.4 `go-fuzz`

`go-fuzz` is a fuzz testing tool for finding potential bugs and vulnerabilities in a program. It tests the program's robustness by generating large amounts of random input data.

**Key features**:
- Automatic test input generation: produces random or patterned input data to test the program's robustness.
- Finding latent defects: helps uncover edge cases and potential errors in the code.

**Install**:
```sh
go get github.com/dvyukov/go-fuzz
```

**Usage example**:
```go
// fuzz.go
package example

func Fuzz(data []byte) int {
    // process the data to test the program's robustness
    if len(data) > 0 {
        _ = string(data)
    }
    return 0
}
```

**Run fuzz tests**:
```sh
# first use go-fuzz-build to produce the archive used for fuzzing
go-fuzz-build
# then run go-fuzz, with -bin pointing at the archive produced in the previous step
go-fuzz -bin=example-fuzz.zip
```

> Note: Go 1.18+ has native fuzz testing built in; prefer `go test -fuzz=Fuzz`, which needs no third-party tool.

#### 6.5 `testcontainers-go`

`testcontainers-go` is a library for starting and managing Docker containers in tests, in order to provide an isolated test environment.

**Key features**:
- Docker container management: start and stop Docker containers within tests.
- Provides isolation: ensures tests run in a consistent environment.

**Install**:
```sh
go get github.com/testcontainers/testcontainers-go
```

**Usage example**:
```go
// example_test.go
package example

import (
    "context"
    "testing"
    "github.com/testcontainers/testcontainers-go"
)

// test example
func TestWithDocker(t *testing.T) {
    ctx := context.Background()
    req := testcontainers.ContainerRequest{
        Image: "redis:latest",
        ExposedPorts: []string{"6379/tcp"},
    }
    redisContainer, err := testcontainers.GenericContainer(ctx, testcontainers.GenericContainerRequest{
        ContainerRequest: req,
        Started:          true,
    })
    if err != nil {
        t.Fatalf("Failed to start container: %v", err)
    }
    defer redisContainer.Terminate(ctx)

    // run the test
}
```

### Summary

The five libraries each cover one slice: `testify` fills in assertions and mocking, `gomock` generates mock code from an interface, `goconvey` offers BDD syntax, `go-fuzz` does fuzz testing (since Go 1.18 the built-in `go test -fuzz` is enough), and `testcontainers-go` starts real dependencies inside Docker for integration tests. Starting with `testify` is the least friction; add the others as the project needs them.
