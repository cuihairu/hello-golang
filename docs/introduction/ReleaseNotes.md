# Version releases and support policy

Go's release cadence and support policy affect how you pick a version for a project and when you upgrade. I've only touched on Go release notes in scattered bits before; this page is put together from the official release-history page and the download endpoint, with data fetched on 2026-10-08.

## 1. Two hard rules

1. **Supported until two major versions back**: in the official words, each major version is supported until two newer major versions have appeared. The example in the docs is Go 1.5 supported until Go 1.7 was released, and Go 1.6 supported until Go 1.8 was released.
2. **Security fixes cover only the two most recent major versions**: the official security page uses the same line, so staying on an old version means you no longer get security patches.

Patch versions (minor revisions) are released as needed, to fix critical issues, including critical security ones.

## 2. The current version lines

| Version | Release date | Notes |
| --- | --- | --- |
| `go1.27.0` | 2026-08-19 | Current major version |
| `go1.27.1` | 2026-09-01 | Fixes in cgo, the compiler, the runtime, `go fix`, `database/sql`, `debug/elf`, `encoding/json`, `net/http`, `os`, `simd`, and more |
| `go1.26.0` | 2026-02-10 | Previous major version |
| `go1.26.1` - `go1.26.8` | 2026-03-05 to 2026-09-01 | Includes several batches of security fixes (`crypto/x509`, `crypto/tls`, `html/template`, `net/url`, `net/http`, and more) |

The two dates 2026-02-10 and 2026-08-19 show the cadence directly: **a major version every half year**. The first entry of the stable-version list returned by `/dl/?mode=json` is `go1.27.1`, consistent with this page.

## 3. How to actually choose

| Scenario | Recommendation |
| --- | --- |
| New project | Just use the current stable version; at the time this page was fetched that was `go1.27.1` |
| Already in production | Follow the latest patch version of the current major version, where security fixes are concentrated |
| A dependency requires a higher minimum version | Look at the dependency's `go.mod`, and upgrade via the toolchain usage in `docs/zh/env/Tools.md` when necessary |
| Want to use a new language feature | Major-version tags accumulate two per year from 1.1 on; see the `go1.N` tags in `docs/zh/start/BuildConstraint.md` |

The `go` directive in `go.mod` decides the available language version, covered in this repo's `docs/zh/mod/Mod.md`; when a build constraint carries a major-version tag, the language version takes the minimum implied by that tag, rules in `docs/zh/start/BuildConstraint.md`.
